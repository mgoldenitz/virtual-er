# Known issues and gotchas

- Norton re-signs HTTPS. Node in the owner's own terminal fails server-side Supabase calls (and the Pushover call in `/api/recall-alert`) without --use-system-ca; `npm run dev` adds it (scripts/dev.mjs). Claude's Bash shell already trusts the certificate, which hides the problem.
- The recall alert route answers `204` and sends nothing when `PUSHOVER_APP_TOKEN` or `PUSHOVER_USER_KEY` is missing or misnamed, so a wrong name in .env.local or Vercel gives no error (2026-11-19). Test the keys first with a direct POST to the Pushover API from PowerShell; `"status": 1` means they work.
- ntfy on iPhone did not show messages on a locked phone, only with the app open (2026-11-19). A `200` from ntfy.sh means sent, not delivered. Replaced by Pushover.
- Python here: `python -I` ignores PYTHONIOENCODING. Use `python -I -X utf8` for Urdu, Arabic, Chinese or symbols. Long heredoc scripts get mangled; write the script to a file first. Put code text that holds a backslash (a regex such as \bmin\b) in a raw string (r'''...'''), or Python changes \b into a backspace.
- Do not edit text that has backslashes (regex, escapes) with `sed` or `printf` in the Bash tool; the shell removes or changes them (`printf` turns `\201` into one byte). Use Edit, or a quoted heredoc (`cat > file <<'EOF'`) for a temporary file.
- Claude Code keeps per-project settings (switched-off MCP servers) under the folder path in ~/.claude.json. Moving the project folder loses them.
- The Supabase MCP is read-only and often fails to connect. The owner runs database changes in the SQL Editor, and also each check file that writes rows, even inside `begin ... rollback` (`survey.sql`, `demo_tick.sql`). Claude runs only the checks that read (`permissions.sql`).
- Playwright MCP cannot sign in as staff; the owner does the staff half of MCP browser checks. The `npm run e2e` tests sign in with the E2E_ test account (2026-11-20).
- Playwright MCP: `target` takes a ref from the last snapshot (for example `e73`), a CSS selector or a locator, never the role text from the snapshot (`combobox "Select language"` fails). Load the tool schema with ToolSearch before the first call. The Playwright browser keeps the language saved by an earlier test; check the language on the first snapshot and switch to English before you read the text.
- The Vercel MCP cannot change firewall settings or list cron jobs; the owner does these in the dashboard.
- Hook scripts: text piped from PowerShell starts with an invisible byte-order mark, so JSON.parse fails and the script exits silently. Strip `\uFEFF` first. In Git Bash, Node does not read paths like /c/Users; test with C:/Users paths.
- navigator.onLine says "online" on Wi-Fi with no internet or behind a hotel or hospital sign-in page (captive portal), so the offline banner does not show there. Accepted for the demo (Gemini review 2026-11-14): the app does not test a real connection. It asks again when the page comes back on screen (`data/useOnline.ts`).

- Some files have CRLF line ends, and multi-line Edit calls can miss on them. Use a small Python edit script in the job's tmp folder that keeps the line ends.
- `formatMinutes` has no day unit: 25 hours shows "25h". Accepted, because no demo visit stays open for a day (Gemini review c2, 2026-11-15).
- happy-dom's `click()` does not move focus to the button. Click tests call `target.focus()` first, as a mouse click or the Enter key does, or focus checks pass or fail for the wrong reason. To test a phone tap (focus stays on the page body), click without `focus()`.
- React puts two state updates from one event into one commit. When the state ends with no change, a `[state]` effect does not run, so a value kept in a ref for that effect can stay and decide a later change. Clear such a ref in the part that sets the next state (as `turnOn` and `turnOff` clear `backgroundFocus`).
- A test that passes before a fix is not proof. Check each new test with a small temporary code change that must make it fail, then put the code back from a copy in the job's tmp folder (not `git checkout`). For a test that searches files for banned text, make one probe for each form of that text (the character, its HTML name and number, its JS and CSS escape codes) and for each file type the test must read. When a review says "no test fails if line X is removed", first find the steps in the app that reach line X. If no steps reach it, report it as a guard, not as a missing test, before the owner chooses.
- One "Recall all" is one UPDATE, so the trigger gives every recalled visit the same `called_at` (`now()` is the transaction start). Any count of call-backs must use `distinct called_at`, or one Recall all counts as many call-backs with gaps of 0. A SQL check that needs call-backs at different times must pause the trigger inside `begin ... rollback` (`supabase/checks/wait_gap.sql`).
- The Supabase SQL Editor shows only the result of the last statement. A check file that reads results at two points (before and after more inserts) must keep the first results in a temp table and show all rows in one last select, and the owner must run the whole file at once (`supabase/checks/wait_gap.sql`).
- In Git Bash, `tail -3` with more than one file fails ('option used in invalid context'); use `tail -n 3`. Never put a check command in the same `&&` chain as an append (`cat >>`): if the check fails, the append has already run, and a second try appends again. Run the append alone, then check.
